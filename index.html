05 / PROVE IT IN A TEST LAB+

This simulator shows a policy idea. It is not evidence that a real 5G network will behave the same way.

  1. Set a hypothesis. Predict when the test network will stop accepting new sessions. The model only represents turning away new synthetic sessions; it does not disconnect active users.
  2. Use an isolated, authorised testbed. Use a private 5G core and gNB with test UEs or a network simulator. Keep public networks and uninvolved users out of the test.
  3. Establish a baseline. Run the planned session mix at normal load, then increase offered load in controlled steps within the lab owner's limits.
  4. Record the evidence. Capture attempted, accepted, and rejected sessions with the reported cause, alongside radio resource use, active UEs, throughput, latency, and packet loss.
  5. Compare and calibrate. Match the model's admission threshold and service trend to one run, tune the assumptions, then check them against a separate run. Report errors and limits.

The gNB handles radio admission and scheduling; PDU session establishment is a separate 5G procedure. Check both layers in the test records. 3GPP TS 38.300 · TS 23.502

Scope: This validates a defensive model in that specific lab. It does not demonstrate or authorise disrupting a public cell.
